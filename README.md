# Разметка бабочек и сравнение моделей

Командный проект по краудсорсингу. Мы собрали 400 фотографий iNaturalist с лицензией CC0, получили рамки от исполнителей Яндекс Заданий и по две независимые проверки каждой фотографии. Затем сравнили Grounding DINO tiny, OWLv2 base и Qwen3-VL-2B-Instruct.

Посылка `submissions/submission.jsonl`, полученная выбранной моделью Qwen3-VL-2B-Instruct, получила **10/10 в Контесте**.

В нашей постановке взрослые моли тоже входят в целевой класс. Это уточнение преподавателя учтено в инструкции, разметке и запросах к моделям. Гусениц, куколок и других насекомых не выделяем.

## Результаты

| Модель | F1@IoU 0,50 | F1@IoU 0,75 | Время на 400 фото |
| --- | ---: | ---: | ---: |
| **Qwen3-VL-2B-Instruct** | **0,8872** | **0,6667** | 845,54 с |
| Grounding DINO tiny, порог 0,30 | 0,8132 | 0,6520 | 141,97 с |
| Grounding DINO tiny, порог 0,20 | 0,6894 | 0,5648 | 141,97 с |
| OWLv2 base | 0,6445 | 0,3686 | 186,96 с |

Это результаты на командных фотографиях по текущему файлу меток. Он ещё не стал окончательным эталоном: **237 фото приняты на ревью, 128 спорные, 35 отклонены**. Исправления в переданной выгрузке не внесены. На 237 принятых фотографиях F1 Qwen равен 0,9284. Этот срез помогает проверить вывод о выборе модели, но не заменяет оценку всего набора.

Отдельный эксперимент менял только порог Grounding DINO: с 0,30 до 0,20. Число найденных объектов выросло на 10, но добавилось 166 ложных срабатываний, поэтому F1 снизился. Оба порога рассчитаны из одного прохода модели; время у них общее.

Метрики считают максимальное паросочетание рамок, затем суммируют TP, FP и FN по всем фотографиям. Полная таблица, включая precision, recall и срезы по размеру и числу объектов, лежит в [model_results/leaderboard.csv](model_results/leaderboard.csv).

## Пересчитать метрики

Для этого достаточно CPU и уже сохранённых предсказаний. Фотографии и веса скачивать не нужно.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements-eval.txt
python evaluate.py --check
```

Команда сверяет расчёт с опубликованной таблицей. Для записи новой таблицы выполните `python evaluate.py` без `--check`. Исправленный файл меток можно передать через `--gold path/to/reference.jsonl`; в нём должны остаться все 400 ID.

Основное сравнение с сохранёнными выводами находится в [compare_models.ipynb](compare_models.ipynb). При `USE_SAVED = True` он использует предсказания из `model_results`. Данные лежат обычными файлами в `data`, дополнительные архивы не нужны.

## Запустить модели заново

Нужен CUDA-сервер с подходящими сборками PyTorch и torchvision. Версии библиотек и устройство исходного прогона записаны в `model_results/*.json`.

```bash
pip install -r requirements.txt
jupyter lab
```

В ноутбуке задайте `USE_SAVED = False` и укажите доступный GPU в `DEVICE`. `SMOKE_TEST = True` обрабатывает три фото. Оригиналы и веса загружаются при первом запуске, прогресс и ошибки сохраняются в локальном кеше.

Модель получает только фотографию. Метки и категория iNaturalist на вход ей не передаются. Qwen использует изображение с длинной стороной до 640 пикселей, жадную генерацию и NMS с IoU 0,70. Запросы, пороги и ревизии весов зафиксированы в коде и файлах конфигураций.

## Конкурсная посылка

Конкурсные 400 фото отличаются от командного датасета. Готовый файл ответов находится в [submissions/submission.jsonl](submissions/submission.jsonl).

Проверить формат без запуска модели:

```bash
python scripts/validate_submission.py submissions/submission.jsonl
```

Сгенерировать предсказания с сохранённой конфигурацией победителя:

```bash
python submit.py data/contest/dataset.jsonl -o submissions/submission.jsonl
```

Скрипт проверяет все 400 ID, координаты, отсутствие ошибок обработки и размер файла. Ручных исправлений конкурсных рамок нет. В Контест загружается JSONL с компилятором `(make) python-handbook`.

## Что лежит в репозитории

- `annotation/` — интерфейс, инструкция, схема полей, настройки основного пула и эталоны экзамена
- `review/` — интерфейс проверки, инструкция, контрольные примеры и настройки пулов
- `data/team/` — источники 400 фото, первичные рамки, экзаменационные ответы и текущий файл меток
- `data/review/` — 800 проверок, статусы всех фотографий и сведения о проекте проверки
- `data/contest/` — отдельный конкурсный датасет
- `model_results/` — предсказания четырёх конфигураций, таблица метрик и настройки победителя
- `submissions/` — отправленная конкурсная посылка

В [описании процесса](docs/process.md) собраны правила разметки, параметры допуска, сведения о ревью и расходы. Идентификаторы исполнителей заменены на согласованные обозначения `worker_…`; связь между первичной разметкой, экзаменами и ревью сохранена.

Фотографии представлены ссылками на оригиналы и сведениями о лицензиях. Веса моделей, изображения, кэш и временные выгрузки в Git не входят.
